### HF4-01 · same-year cluster Mockup B · `413ba2d`

7 May verify confirmed the R28-S1-FEAT3 / R28-HF3-CONST1 vertical-stagger approach is geometrically wrong for dense-year clusters. The 570 CE cluster has three long titles that physically can't fit using vertical stagger — and increasing the offset cascades, pushing 574 CE and 500 CE rows.

Replaced with the locked **leader-line label cluster** (Khaled's Mockup B):
- Same-year events share one anchor (the year's natural timeline position)
- N events render as a tight vertical dot stack at that anchor (gap 7 px)
- Dashed gold leader lines fan horizontally to a labels column 90 px to the side
- Each label sits at its leader endpoint, vertically spread by 24 px for readability
- A single year label (e.g. "570 CE") sits on the OPPOSITE side, vertically centered against the dot stack's middle
- Constellation lines from adjacent years connect to the cluster's center point (one well-defined target)

Geometry is stable: N events in one year doesn't move surrounding years. The cluster occupies its single year-slot regardless of N — fixes the "stretching timeline" cascade from the stagger approach.

`lib/widgets/constellation_view.dart` — substantial rewrite:
- `_generatePositions` no longer applies symmetric stagger. For cluster events all `positions[k]` point to the same anchor. The `clusterStaggerY = 32` and `clusterSpread = 0.18 × W` constants from FEAT3/HF3-CONST1 are deleted.
- New `_computeLabelPositions(dots)` helper returns per-event LABEL positions (used by both painter + tap-target builder).
- New cluster-geometry constants: `_clusterDotGapY = 7`, `_clusterLabelGapY = 24`, `_clusterLabelOffsetX = 90`, `_clusterYearOffsetX = 50`.
- Tap-target loop: cluster events get a 130 × 26 region at label position (much larger touch target than the 8-px dot). Singletons keep the existing 44 × 44 region at the star.
- `_SkyPainter` split into `_paintSingleStar` (singleton render unchanged) and `_paintCluster` (new leader-line + dot-stack + year-label rendering). Constellation lines skip intra-cluster pairs (same-year, same-anchor — degenerate).
- New `_drawDashedLine` helper (3-px dash, 2.5-px gap, 0.5-px stroke).

AR locale: cluster mirrors horizontally — labels column on the LEFT, year label on the RIGHT, leader lines extend leftward. Mirror is automatic via `_isAr` checks. Constellation lines + dot positions don't horizontally flip (timeline geometry is direction-neutral, per spec).

**Diff:** 424 +, 141 − (single file — net +283 LOC).

### HF4-03 · pinch-to-zoom + 2D pan on Stars view · `c8fc67f`

7 May verify: dense-year regions felt cramped. The standalone Stars screen (retired R28-S1-CODE1) had let users explore detail up close — the absorbed view didn't have an equivalent.

`lib/widgets/constellation_view.dart` — `SingleChildScrollView` replaced with `InteractiveViewer`:
- `transformationController: _transformCtrl` — Matrix4 reset on view-enter (initState post-frame) places the user's current star centered in the viewport
- `constrained: false` — preserves the canvas's natural ~10000-px height so labels stay legible at zoom 1.0 (constrained:true would compress the timeline to viewport height, making every label microscopic)
- `minScale: 1.0`, `maxScale: 3.5` per spec
- `boundaryMargin: EdgeInsets.all(200)` — pan can drift 200 px beyond canvas edges before bounce-back
- Default `panEnabled` — single-finger pan works at any scale, including 1.0 (vertical scroll-equivalent navigation survives)

Replaced: prior `ScrollController _scrollCtrl` removed; prior `_scrollToCurrentStar()` renamed to `_resetAndCenterOnCurrent()` and reimplemented as `Matrix4.translationValues(0, -translateY, 0)` on the transform controller. Journey-complete edge: lands at the bottom of the canvas.

Auto-fit on view-enter: when the LIST → STARS toggle flips, the parent `_EventListScreenState` ternary `_viewMode == list ? ... : ConstellationView(...)` unmounts ConstellationView and remounts, so initState fires and the post-frame callback resets the matrix. For navigations away-and-back to Events List with Stars as default, ConstellationView's State persists; if Khaled wants hard-reset on every entry-from-elsewhere too, RouteAware + didPopNext is the follow-up surface (flagged but not landed).

Tap targets: HF4-01's 130 × 26 cluster-label regions and 44 × 44 singleton regions both scale with the canvas via InteractiveViewer's transformation. Taps still hit at any zoom level.

## Surprises encountered during implementation

- **HF4-05 spec hypothesis was wrong direction.** Spec said "Dhikr nav button doesn't have its TutorialKey registered" — actually the key + widget attachment were present from HF3-TUT1; the miss was the step list entry. Diagnostic-first caught it before a wrong fix shipped.
- **HF4-05 spec count vs UX.** Spec asked for "exactly 6 entries" with a combined `info_settings` step. Went with 7 (kept Info tab + Settings separate) for tooltip clarity. Flagged for Khaled's call on A56 verify.
- **HF4-03 InteractiveViewer constrained-mode trade-off.** Spec phrasing "constellation fits the screen at default zoom" + "min zoom 1.0× full-fit" reads as `constrained: true` (canvas fits viewport at scale 1.0). But that would compress the 10000-px-tall canvas into a ~700-px viewport at zoom 1.0 — labels microscopic. Went with `constrained: false` (natural-size canvas + pan/zoom) since legibility at the default zoom is more important than literal fit-to-screen. Khaled's call on whether to revisit.
- **HF4-01 RTL mirror ordering.** Cluster's labels column (LTR right / RTL left) and year label (LTR left / RTL right) sit on OPPOSITE sides. Spec says "mirror cleanly" but doesn't specify which side flips first. Implemented so both flip together — labels stay on the "first read direction" side, year on the opposite. If A56 reads weird, both `_isAr` ternaries are colocated for an easy swap.
